## BLOCKER 1 — Structured identifier fields outside data_sources promote UNMAPPED (silent source leak)
Location: promotion/mapping.py ~109-114 (MappingTransformer.render structured loop) + ~81-96 (map_executable_fields). Also promotion/__init__.py ~122-127 (preflight resources) and promotion/packages.py ~44-45 (packages.build required_sources).
Problem: render maps `identifier` only under data_sources.{tables,metric_views,catalogs,schemas}. A bare `identifier` key elsewhere is neither an env key nor in {expression,sql_expression,query,function_name}, so map_executable_fields recurses and leaves it UNTOUCHED. Per schema.md:110,117-118, `instructions.join_specs[].left/right.identifier` and `instructions.sql_functions[].identifier` are three-level catalog.schema.name identifiers. Result: promoted target space references SOURCE tables/functions (a silent wrong-environment write = F-PROMOTION), and preflight never validates consumer/executor access to those join relations + UDFs.
FIX: drive identifier traversal from an EXPLICIT allowlist of every identifier-bearing path in schema.md (at minimum: data_sources.{tables,metric_views,catalogs,schemas}.identifier, instructions.join_specs[].left.identifier, instructions.join_specs[].right.identifier, instructions.sql_functions[].identifier). Map each EXACTLY via the existing identifier mapping. Any UNRECOGNIZED `identifier` key encountered during traversal must RAISE (fail-closed) rather than pass through, so a future schema field can never silently leak. Extend preflight's `resources` set and packages.build's `required_sources` to include the join-relation and sql_function identifiers from the SAME allowlist, so access is validated and the package pins them.
RED test (test_vc_mapping.py): test_join_specs_and_sql_function_identifiers_map_exactly_or_fail_closed — render a serialized_space carrying instructions.join_specs.left/right.identifier and sql_functions.identifier; assert each is rewritten to its mapped target value; and assert an UNMAPPED identifier raises ValueError. Fails today (returns source identifiers unchanged). PLUS in test_vc_promotion.py assert dependencies.check (or the access-validation port) is called for the join and function identifiers for BOTH executor and consumer.

## BLOCKER 2 — SQL fragment fields unpromotable + override path corrupts fragment array arity
Location: promotion/mapping.py ~21-23 (override recursion) and ~88-91 (`[rendered] if fragments`).
Problem: map_sql requires code[0].upper()=='SELECT', but join_specs.sql and sql_snippets.filters/expressions/measures[].sql are FRAGMENTS not statements. The `sql:` reviewed override cannot rescue them because the override is recursively re-validated by the same SELECT-only gate (so the escape hatch module-07 §5 task 5 promises does not work). SEPARATELY: when an override DOES apply to a multi-element array, `value[key] = [rendered]` collapses it to ONE element — but join_specs.sql must be exactly 2 elements and schema.md:204 says the API REJECTS a request whose join_specs.sql lacks the second `--rt=` annotation. So an applied override silently corrupts.
FIX: (a) add a fragment-mode path — either identifier-map over a non-statement token stream, OR an explicit reviewed FRAGMENT-override keyspace that is NOT re-validated as a SELECT statement — so reviewed fragments can promote. (b) NEVER collapse an N-element sql array to one: preserve arity, mapping element 0 (the SQL/condition) and preserving the trailing annotation element(s) (e.g. `--rt=...--`) byte-identical.
RED test (test_vc_mapping.py): test_join_spec_and_snippet_sql_fragments_map_identifiers_and_preserve_arity — a join_specs entry with the real two-element [condition, '--rt=...--'] shape (see schema.md:204 for exact form); assert identifiers in element 0 are mapped, len(sql)==2, and element 1 is byte-identical to input. Also a sql_snippets measure fragment maps or is rescued by a reviewed fragment override. Fails today (raises, or collapses to 1 element under override).

## BLOCKER 3 — portable() env-stripping is dead code; nested source env IDs published to cross-workspace-readable package; test tautological
