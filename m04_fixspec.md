## B1 — IMPLEMENTATION DEFECT: pre-send base conflict bricks the binding (FM-DRIFT)
- Location: `backend/services/version_control/mutation_gate.py:41-43` (the reviewed-base-mismatch branch that calls `self.coordination.quarantine(reservation.fence, "Reviewed base changed before admission")` and returns CONFLICTED).
- Violates: contract §5.3 ("stale reviewed base → preserve external state and publish `conflicted`; NO PATCH") and FM-DRIFT (this is the ordinary "someone edited the agent in the Genie UI while your tab was open" case). §5.9's "lease expiry / base equality insufficient" is about AMBIGUOUS POST-SEND, not proven pre-send rejection.
- Verified against real M03: quarantine() on the reservation fence sets state=QUARANTINED, unresolved=True → subsequent reserve() is BLOCKED ("unresolved attempt already owns this binding"), capture_on_open returns busy+stale, recover() is disabled (needs trusted termination + verified request-lifetime). Binding is unusable for reads AND writes; only audited break-glass unsticks it.
- M03 already provides the correct primitive: its pre-send rejection path publishes a terminal CONFLICTED fact then _release()s the row (guarded by _presend(row)), leaving state=IDLE, unresolved=False. M03's own test_terminal_non_success_receipt_is_a_conflict_not_a_completion asserts this shape. The gate must USE that path, not quarantine.
- REQUIRED FIX: on a pre-send reviewed-base mismatch, do NOT call quarantine. Publish the terminal CONFLICTED fact and release the reservation through M03's pre-send rejection seam (e.g. finish(claim/reservation, OperationResult(..., CONFLICTED, ..., unresolved=False, ...)) on a proven pre-send row, or the explicit reject seam M03 exposes). Reserve quarantine() for POST-SEND ambiguity only. Preserve external preimage in the returned result.
- REQUIRED RED TEST: `test_pre_send_base_conflict_releases_binding_without_quarantine` in `backend/tests/test_vc_mutation_gate.py` — assert result status CONFLICTED, NO PATCH sent, external preimage preserved, `coordination.quarantine.assert_not_called()`, AND a subsequent `reserve()` for a corrected request SUCCEEDS (binding not bricked). Must fail against the current quarantine() implementation.
